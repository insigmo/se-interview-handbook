🐍 Python — базовые вопросы

Изменяемые и неизменяемые типы

Изменяемые можно менять без создания нового объекта (list, dict). Неизменяемые — при изменении создаётся новый объект (int, str, tuple). Важно для понимания побочных эффектов.

Декораторы

Функции, которые расширяют поведение других функций без изменения их кода. Используются для логирования, ретраев и вспомогательной логики в тестах.

Итераторы и генераторы

Итератор — объект, по которому можно проходиться поэлементно. Генератор — упрощённый итератор с yield, экономит память.

@abstractmethod и @property

abstractmethod — задаёт обязательный интерфейс. property — позволяет обращаться к методу как к атрибуту, сохраняя инкапсуляцию.

ООП: инкапсуляция, наследование, полиморфизм

Инкапсуляция — сокрытие реализации.
Наследование — переиспользование кода.
Полиморфизм — один интерфейс, разное поведение.

copy vs deepcopy — в чём разница?

copy создаёт поверхностную копию объекта — вложенные объекты остаются общими. deepcopy рекурсивно копирует все вложенные объекты. Использую deepcopy, когда важно избежать побочных эффектов.

Как бы ты читал файл размером несколько гигабайт?

Читал бы файл по частям, используя итерацию по строкам или чтение чанками, чтобы не загружать весь файл в память.

Чем отличается list comprehension от генератора?

list comprehension сразу создаёт список в памяти. Генератор вычисляет значения по мере необходимости, что экономит память при работе с большими объёмами данных.

Что такое контекстный менеджер?

Контекстный менеджер управляет ресурсами, например, автоматически закрывает файл или соединение после выхода из блока with.

Как работает обработка исключений?

Исключения позволяют обрабатывать ошибки без падения программы. Использую try/except/finally для безопасной работы с ресурсами.

Почему не стоит использовать mutable объекты по умолчанию?

Потому что они создаются один раз при объявлении функции и могут привести к неожиданным побочным эффектам между вызовами.

Когда имеет смысл использовать yield?

Когда нужно обрабатывать большие объёмы данных или строить ленивые вычисления, не занимая лишнюю память.

Что происходит при передаче аргументов в функцию?

В Python передаётся ссылка на объект. Для неизменяемых типов создаётся новый объект, для изменяемых — возможны побочные эффекты.

Как бы ты объяснил GIL на базовом уровне?

GIL ограничивает выполнение байткода Python одним потоком, что важно учитывать при CPU-нагруженных задачах.

🧪 Pytest

Что такое pytest

Фреймворк для написания и запуска автотестов на Python. Используется для UI и API тестирования.

Фикстуры

Используются для подготовки данных и окружения тестов. Заменяют setup/teardown.

Scope, параметризация, маркеры

Scope — как часто создаётся фикстура. Параметризация — запуск теста с разными данными. Маркеры — группировка тестов.

Conftest.py

Файл для общих фикстур и настроек. Работает автоматически, без импортов.

Параллельный запуск тестов (pytest-xdist)

Использовал pytest-xdist для параллельного выполнения тестов. Это сокращает время прогона регресса. Учитывал ограничения: изоляцию данных, работу с БД и внешними сервисами.

Что такое flaky-тесты и как ты с ними боролся?

Flaky-тесты — нестабильные тесты с непредсказуемым результатом. Я выявлял причины, устранял зависимости от таймингов и окружения, а ретраи использовал только как временную меру.

pytest.mark.skip и xfail — в чём разница?

skip — тест не должен выполняться. xfail — тест ожидаемо падает из-за известного дефекта, но продолжает давать информацию о его состоянии.

pytest hooks — что это и зачем они нужны?

Hooks позволяют влиять на жизненный цикл тестов: добавлять логирование, модифицировать отчёты, управлять поведением тестов на уровне фреймворка.

Как ты структурируешь проект с автотестами?

Разделяю тесты по уровням и функциональности, использую conftest.py для общих фикстур, выношу бизнес-логику и клиенты в отдельные модули.

Как работаешь с параметризацией?

Использую параметризацию для проверки разных сценариев без дублирования кода, что повышает читаемость и поддержку тестов.

Как pytest интегрируется в CI/CD?

pytest легко встраивается в пайплайны, позволяет управлять маркерами, отчётами и кодом возврата, что удобно для автоматического принятия решений в CI.

Какие отчёты по автотестам ты использовал?

Использовал стандартные pytest-отчёты, а также интеграцию с Allure или собственные отчёты, которые были понятны не только QA, но и бизнесу.

Почему ты выбрал pytest, а не unittest?

pytest проще в использовании, гибче, имеет развитую экосистему плагинов и лучше подходит для масштабируемых автотестов.
